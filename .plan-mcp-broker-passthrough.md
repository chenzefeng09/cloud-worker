## Problem
In `SCHEDULER_SANDBOX_EGRESS_MODE=broker` (default), the sandbox joins ONLY
`agent-platform-dev_sandbox_broker` (internal, no foundation network). The Claude SDK
worker's `loadMcpServers`/`mapRegistryServer` (worker-claude-sdk/src/worker.ts) hands the
SDK the RAW registry `endpoint` (e.g. http://echo-mcp:9000/mcp). That host is unreachable
from the sandbox → SDK MCP connection fails open → tenant tools never surface. The OLD
agentscope worker had the same latent bug (it also dialed the raw endpoint); there is NO
existing working reference. Fix must be built fresh.

## Design (decided with user)
- **Worker rewrites (TS):** in broker mode, rewrite each tenant MCP server's `endpoint` to a
  broker passthrough route keyed by the server's `id`.
- **Broker passthrough keyed by server id:** new route `/mcp-tenant/v1/{server_id}/{path}`.
  Broker validates the per-run lease (new scope `mcp.tenant_invoke`), derives `tenant_id`
  from the lease, looks up the server's `endpoint` from the mcp-registry by
  `(tenant_id, server_id)` via the existing `internal/mcp-servers` list, and proxies to it
  reusing `_proxy`'s SSE-streaming machinery.

## Key verified facts
- Registry `GET /api/mcp/v1/internal/mcp-servers?tenant_id=...` returns `{items,total}`; each
  item has `id` (`mcp_<26hex>`, global PK), `tenant_id`, `name`, `transport`, `endpoint`, ...
  Returns ENABLED servers only (disabled → silently dropped = failure-open, desired).
  Auth: header `X-Service-Scopes` must contain `mcp.read_internal` AND `X-Tenant-Id` header
  must equal the `tenant_id` query param. (mcp-registry api/dependencies.py:52-71)
- No `GET /internal/mcp-servers/{id}` exists → broker must list + filter by id client-side.
- SDK HTTP MCP config shape: `{ type:"http"|"sse", url, headers? }`
  (worker-claude-sdk/node_modules/@anthropic-ai/claude-agent-sdk/.../runtimeTypes.d.ts:38-47).
  Registry transport enum only stores `http`/`stdio` (no `sse`), but worker tolerates `sse`.
- Broker `_proxy` already streams `text/event-stream` and has a per-scope upstream allowlist;
  upstreams are otherwise hardcoded. (services/tool-broker/src/tool_broker/main.py)
- Broker `_ALLOWED_METHODS = {GET,POST,HEAD}` (main.py:82) — streamable-http MCP also uses
  DELETE for session teardown → MUST add DELETE for the tenant route.
- Lease minted by scheduler with `BROKER_LEASE_SCOPES`
  (agent-scheduler/.../services/egress_policy.py:18-32) — new scope must be added there too,
  AND must be shared-secret HMAC compatible (same secret both sides; already wired).
- Sandbox env in broker mode already carries `TOOL_BROKER_URL`
  (=`http://tool-broker:8024/api/tool-broker/v1`), `SANDBOX_EGRESS_MODE`,
  `FOUNDATION_TENANT_ID`, `TOOL_BROKER_LEASE`. (egress_policy.service_env:137-171;
  docker_runtime.py:329; cube_runtime.py:319). NOTE: worker.ts currently does NOT read
  `SANDBOX_EGRESS_MODE` into its Env snapshot — task.ts readEnv must add it (env var name is
  `SANDBOX_EGRESS_MODE`, set by runtime, distinct from scheduler's
  `SCHEDULER_SANDBOX_EGRESS_MODE`).
- `TOOL_BROKER_URL` IS read from process.env in redis_state.ts, and is in
  `TOOL_ENV_SCRUB_KEYS` (main.ts:65) — scrubbed AFTER loadMcpServers runs (main.ts:241 then
  scrub at :246), so reading it during loadMcpServers is safe.

## Workstreams

### WS1 — tool-broker: add `/mcp-tenant/v1/{server_id}/{path}` passthrough route
File: services/tool-broker/src/tool_broker/main.py (+ config.py, + tests)
- New scope constant `mcp.tenant_invoke`.
- New `@router.api_route("/mcp-tenant/v1/{server_id}/{path:path}", methods=[GET,POST,HEAD,DELETE])`.
  Add DELETE to `_ALLOWED_METHODS` (or pass a per-route allowed-methods override so DELETE is
  only enabled on this route — prefer not to globally widen; check how _proxy enforces methods).
- Handler:
  1. `_require_auth` + `_require_lease(required_scope="mcp.tenant_invoke")` → get lease payload
     (tenant_id, user_id).
  2. Resolve endpoint: call mcp-registry `GET {mcp_registry_url}/internal/mcp-servers?tenant_id=<lease tenant>`
     with `X-Service-Scopes: mcp.read_internal` + `X-Tenant-Id: <lease tenant>` (same trusted
     header injection _proxy already does for the registry route). Filter items by
     `id == server_id`. Not found / disabled → return 404 (worker treats as drop = failure-open).
     Consider a tiny per-request cache only if trivial; otherwise one lookup per call is fine.
  3. Forward to `{endpoint}` + `/{path}` via the existing `_proxy` streaming machinery
     (reuse `_iter_upstream`/StreamingResponse). The tenant MCP endpoint already includes its
     own path (e.g. .../mcp); `{path}` is appended by the SDK's MCP client. Verify path joining:
     SDK posts to the configured `url` directly (no extra path) for streamable-http, and to
     `url` for SSE GET — confirm what `{path}` actually carries in practice and join correctly.
  4. Headers toward the tenant upstream: do NOT inject foundation identity unless the registry
     manifest carried `headers` (tenant servers are third-party). Strip the lease + sandbox
     identity headers (reuse `_HOP_BY_HOP_REQUEST_HEADERS`). The tenant endpoint is internal to
     foundation network (broker is dual-homed) so it's reachable from broker.
- Upstream allowlist: the existing `_UPSTREAM_ALLOWLISTS` is keyed by required_scope + fixed
  upstream base. Here the upstream base is DYNAMIC (the resolved endpoint) and the path is the
  MCP protocol path. Decide: either (a) skip the static-path allowlist for this route since the
  upstream itself is registry-vouched (endpoint came from the trusted registry, not the
  sandbox), or (b) add a permissive allowlist entry. SSRF is bounded because the sandbox only
  supplies `server_id` (an opaque key); the actual URL comes from the registry. Document this.
- config.py: reuse `mcp_registry_url` (already present) for the lookup.
- Tests (services/tool-broker/tests/test_tool_broker.py): lease scope enforced; unknown
  server_id → 404; happy-path proxy to a stub upstream; DELETE allowed; disabled server → 404;
  tenant mismatch (lease tenant vs a server of another tenant) → 404.

## Crux / risk — RESOLVED ✓
Confirmed from the vendored SDK bundle
(worker-claude-sdk/node_modules/@anthropic-ai/claude-agent-sdk/cli.js, SDK v0.1.77, bundled
MCP transports): for BOTH `type:"http"` (StreamableHTTPClientTransport) and `type:"sse"`
(SSEClientTransport), the config `headers` are stored as `_requestInit.headers` and re-merged
via `_commonHeaders()` on EVERY outbound request (every JSON-RPC POST / tool call, plus the SSE
GET stream + per-message POST-back). So a STATIC `x-tool-broker-lease` header placed in the SDK
MCP server config IS sent to the broker on every request. Header-based lease design is sound;
no query-param/path-token fallback needed.
=> WS3 attaches `headers: { "x-tool-broker-lease": env.TOOL_BROKER_LEASE }` (plus any
manifest headers) on the rewritten http/sse config. The broker's `_require_lease` reads
`X-Tool-Broker-Lease` on every call — consistent.
